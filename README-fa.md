# پنل تک‌فایلی

یک اپلیکیشن FastAPI که روی هر هاست ASGI اجرا می‌شود: یک فایل پایتون، وابستگی‌های
پین‌شده، بدون دیتابیس جدا، بدون ایمیج داکر و بدون گواهی.

به‌صورت پیش‌فرض یک **سایت پوششی تصادفی** هم همراه آن است: هر مسیر عمومی به‌جای
پنل، یک سایت کوچک و بی‌ربط (چند کیلوبایت، بدون اسکریپت، بدون فونت خارجی و بدون
هیچ درخواست شخص ثالث) را برمی‌گرداند. رابط واقعی پشت یک مسیر محرمانه می‌ماند، پس
بازدیدکننده یا اسکنر خودکار فقط یک سایت معمولی می‌بیند.

```bash
pip install -r requirements.txt
gunicorn -k uvicorn.workers.UvicornWorker main:app --bind 0.0.0.0:$PORT --timeout 0
```

## سایت پوششی

| متغیر | پیش‌فرض | کار |
|---|---|---|
| `COVER_MODE` | `1` | سایت پوششی روی مسیرهای عمومی فعال است، `0` غیرفعال |
| `COVER_KEY` | مشتق‌شده از `SECRET_KEY` | مسیر محرمانه‌ای که پوشش را برمی‌دارد |
| `COVER_REVEAL` | `0` | چند ثانیه بعد از بوت، پوشش خودش برداشته شود |
| `COVER_BRAND` | – | تعیین دستی نام سایت |
| `COVER_SEED` | – | تعیین دستی seed؛ با یک seed همیشه یک سایت ساخته می‌شود |

مسیر بازکردن پوشش یک‌بار هنگام استارت چاپ می‌شود:

```
[cover] public paths answer with a random site (Vela Supply). Panel unlock path: /5eadb001f2b7
```

با باز کردن `/<COVER_KEY>` یک کوکی ماندگار ست می‌شود و از آن به بعد پنل عادی پاسخ
می‌دهد. تا قبل از باز کردن پوشش، این‌ها کار می‌کنند چون کلاینت‌ها به آن‌ها نیاز
دارند: اینباندهای پروکسی، لینک‌های اشتراک، SVG پرچم‌ها و `/healthz`. مسیرهای
`/api/` تا باز شدن پوشش `404` برمی‌گردانند.

**دو مرحله‌ای دیپلوی.** فایل `cover_site.py` همین سایت را به‌صورت فایل‌های ساده
می‌نویسد؛ یعنی اول سایت سبک روی هاست بالا می‌آید و بعد خود اپلیکیشن، روی همان دامنه:

```bash
python cover_site.py --out ./site
python cover_site.py --out ./site --serve 8080
```

## تنظیمات

| متغیر | پیش‌فرض | کار |
|---|---|---|
| `SECRET_KEY` | تصادفی | امضای کوکی نشست — حتماً مقداردهی شود |
| `DOMAIN` | – | دامنه عمومی بدون پروتکل |
| `WS_PATH` | `ws` | مسیر اینباند اول |
| `XHTTP_PATH` | `xh` | مسیر اینباند دوم (باید متفاوت باشد) |
| `XHTTP_MODE` | `stream-up` | شکل آپ‌لینک در لینک‌های تولیدشده |
| `RELAY_DOMAIN` | – | دامنه ریلوی؛ همه لینک‌ها به آن اشاره می‌کنند |
| `RELAY_LOW_COST` | `1` با ریلوی | کاربر جدید روی ترنسپورت ارزان شروع می‌شود |
| `ADMIN_PASSWORD` | – | پیش‌تنظیم رمز و حذف صفحه راه‌اندازی |
| `DB_PATH` | `/tmp/panel.db` | فایل SQLite؛ برای ماندگاری روی volume تنظیم شود |
| `DEVICE_WINDOW` | `300` | ثانیه‌ای که یک IP دستگاه فعال حساب می‌شود |
| `SESSION_IDLE` | `90` | ثانیه تا رها شدن نشست بی‌اتصال |
| `PANEL_TITLE` | `Panel` | عنوان پنل |
| `KEEPALIVE` | `0` | پینگ دوره‌ای برای جلوگیری از خوابیدن هاست |
| `COVER_*` | بالا | سایت پوششی |

## مصرف ریلوی

ریلوی جلوی اپلیکیشن به‌ازای **هر درخواست** حساب می‌شود و ترنسپورت‌ها هزینه‌ی
یکسانی ندارند:

| مسیر | تعداد درخواست به ازای هر اتصال |
|---|---|
| `ws` | **۱** — یک درخواست برای کل عمر تونل |
| `xhttp` (`stream-up`) | ۲ — یک `GET` جریانی پایین، یک `POST` بلند بالا |
| `xhttp` (`packet-up`) | ۱ + یکی به ازای هر chunk آپلود — صدها در دقیقه برای هر کلاینت |

برای کمترین مصرف:

* `XHTTP_MODE=stream-up` بماند (پیش‌فرض همین است)؛
* وقتی ریلوی تنظیم است، کاربر جدید به‌صورت پیش‌فرض روی `ws` ساخته می‌شود — یعنی
  یک درخواست برای کل اتصال. با `RELAY_LOW_COST=0` این رفتار خاموش می‌شود؛
* پشت ریلوی متریک از `packet-up` استفاده نکنید؛ سرور در هر دو حالت پذیرا می‌ماند
  پس لینک‌های قبلی خراب نمی‌شوند.

## ذخیره‌سازی

دیتابیس SQLite است. `DB_PATH` را روی volume (`/data/panel.db`) بگذارید وگرنه با هر
دیپلوی دوباره پاک می‌شود. ستون‌های جدید خودکار اضافه می‌شوند، پس ارتقا درجا امن است.

## پشتیبان و بازیابی

*پنل → تنظیمات → پشتیبان* یک فایل JSON می‌سازد که شامل همه کاربرها، شناسه و توکن
اشتراکشان، لیست آدرس‌ها، هش رمز و محیط اجرای برنامه است. بازیابی همین فایل را
برمی‌گرداند؛ به‌صورت ادغام با داده فعلی یا جایگزینی کامل. شناسه‌ها حفظ می‌شوند،
پس کانفیگ‌های نصب‌شده روی کلاینت‌ها بعد از مهاجرت هم کار می‌کنند.
